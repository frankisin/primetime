Practice Problem: Task Scheduler / Job Queue

You are implementing an in-memory task scheduling system.
Process a list of queries in order. Each query returns a string.

The system starts with no tasks.

Core Concepts

Each task has:
a unique taskId (string)
a runAt time (integer)
a priority (integer, higher = more important)
Time is represented as integers and is provided explicitly in queries
Tasks are executed only when the current time is >= runAt
Tasks execute once and are removed after execution
If multiple tasks are ready, execution order matters

Execution Rules (VERY IMPORTANT)
When executing tasks:
Higher priority executes first
If priorities tie, earlier runAt executes first
If both tie, lexicographically smaller taskId executes first

Operations
1) SCHEDULE taskId runAt priority
Schedule a new task.
Rules:
taskId must be unique
runAt and priority are integers

Return:
"true" if scheduled successfully
"false" if taskId already exists

2) CANCEL taskId
Cancel a scheduled task.
Rules:
Task must exist
Cancelled tasks are removed and never executed
Return:
"true" if cancelled
"false" if task does not exist

3) RUN time
Execute all tasks whose runAt <= time, following execution rules.
Rules:
Tasks execute one by one
Each executed task is removed from the system
Return:
Comma-separated list of executed taskIds in execution order
"" if no tasks are executed

4) NEXT_TASK time
Peek at the next task that would execute at the given time without removing it.
Rules:
Only consider tasks with runAt <= time
Do not mutate state
Return:

taskId of the next task
"" if no task is ready

Output
Return a list of strings — one per query — in the same order as input.

Example Queries

SCHEDULE task1 5 10
SCHEDULE task2 5 20
SCHEDULE task3 3 15
RUN 4
RUN 5
NEXT_TASK 10
Outputs
"true"
"true"
"true"
"task3"
"task2,task1"
""

Notes / Constraints
Up to ~10⁴ operations
Favor efficient ordering (priority queue / heap)
State must not change on failed operations
Do not scan the full task list on every operation if avoidable
Suggested approach (mental, not code)
Identify the state
Decide what structure enforces ordering
Be careful with ties
Treat RUN and NEXT_TASK differently (mutating vs non-mutating)
